# Set up the shopping starter

Run `./dev setup` with Git, Python 3.11+, Node 22+, and npm installed. The script reconstructs the pinned upstream source and installs dependencies into `.runtime/commerce-agents`. It creates `.env` with file permissions restricted to your user and generates the encryption key. Existing configuration is preserved.

## Account values

| Variable | Where it comes from | Used for |
| --- | --- | --- |
| `ANTHROPIC_API_KEY` | Your Anthropic account | Run the shopping conversation |
| `CONTO_ORG_API_KEY` | Conto integration onboarding | Create session agents and configure demo policies |
| `CONTO_OWNER_MEMBERSHIP_ID` | Conto integration onboarding | Associate demo agents and approvals with their owner |
| `CONTO_SHARED_WALLET_ID` | A dedicated Conto testnet wallet configured during onboarding | Supply the wallet context for authorization; no wallet transfer is executed |
| `STRIPE_TEST_SECRET_KEY` | Your Stripe test environment; must start with `sk_test_` | Create and verify test Checkout Sessions |
| `SHOPPING_SESSION_ENCRYPTION_KEY` | Generated by `./dev setup` | Encrypt server-side session credentials |

[Request Conto starter access](https://conto.finance/contact) and ask for the organization key, owner membership ID, and a dedicated testnet wallet suitable for the example's policy limits. The code currently uses a wallet-backed Conto payment request with `autoExecute: false` to obtain an authorization decision. That is why a wallet ID is needed even though Stripe performs checkout.

Fill in the five account values, then run `./dev doctor`. It checks required values, Stripe test-key format, encryption-key length, URL format, and paired KV settings. It does not verify that remote accounts or credentials work.

## Start and validate

Run `./dev start`, then visit http://localhost:3000. Free ports 8000 and 3000 first; the launcher stops if they are occupied so checkout return URLs stay predictable. `SHOPPING_AGENT_ORIGIN` defaults to the API origin, http://localhost:8000. The frontend launcher supplies its API URL separately.

The first connected shopping session can create resources in your configured Conto organization. Use a dedicated sandbox organization or resources agreed during onboarding. Local state is held in memory and resets with the process; your hosted Conto resources are separate and are not automatically deleted by stopping the app.

## Troubleshooting

| Symptom | Next check |
| --- | --- |
| Setup reports an old Python or Node version | Select Python 3.11+ with `PYTHON_BIN` and Node 22+ before rerunning setup |
| Doctor reports missing values | Fill `.env` at this repository's root; check for empty shell variables overriding file values |
| Chat cannot run | Check the Anthropic key and account access; inspect the API terminal output |
| Controls cannot initialize | Confirm the organization key, owner membership, wallet, and delegated limits with Conto |
| Checkout is blocked | Read the displayed purchase checks; distinguish a policy decision from a setup failure |
| Stripe checkout cannot open | Verify a test secret key and that the purchase is approved |
| A return URL points to the wrong host | Check `SHOPPING_AGENT_ORIGIN` and restart the backend |
| Webhooks fail verification | Set the signing secret for this exact endpoint, then restart or redeploy |

Do not paste credentials into issues or screenshots. `./dev doctor` prints variable names and corrective instructions, never their values.
